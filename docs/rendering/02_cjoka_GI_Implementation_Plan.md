# cjoka Engine -- Advanced GI & Rendering Implementation Plan

## Введение
Наш движок `cjoka` использует Forward-рендеринг на базе OpenGL 4.6 с поддержкой PBR, HDR, Bloom и базового Shadow Mapping. Чтобы приблизиться к графике уровня Unreal Engine (и идеям Lumen), оставаясь в рамках Forward-пайплайна и OpenGL 4.6 (без аппаратного DXR), мы должны внедрить поэтапный план модернизации рендера.

---

## Этап 1: Forward+ (Clustered Shading)
Текущая проблема: ограничение в 16 Point Lights из-за лимита Uniform-массивов. В длинной демо-сцене (500м) это фатально.

**Реализация:**
1. Разбить камерный фрустум на 3D-сетку кластеров (например, 16x9x24).
2. Compute Shader (вызывается перед Forward-пассом) пересекает все источники света с кластерами и записывает индексы пересекающихся источников в SSBO (Shader Storage Buffer Object).
3. В `kLitFS` (Forward Shader) фрагмент вычисляет свой индекс кластера (на основе экранных координат и `gl_FragCoord.z`), читает из SSBO список источников и обрабатывает только их.
**Итог:** Поддержка тысяч динамических источников света (фары, фонари, частицы) без падения FPS.

---

## Этап 2: Cascaded Shadow Maps (CSM) & Volumetrics
Текущая проблема: одна карта теней не может покрыть трассу в 500 метров без гигантской потери разрешения (пикселизации).

**Реализация:**
1. **CSM**: Разделить frustum камеры на 3-4 каскада (например, 0-15м, 15-50м, 50-150м, 150-500м).
2. Рендерить тени в `GL_TEXTURE_2D_ARRAY`.
3. В шейдере выбирать слой массива на основе дистанции от камеры до фрагмента, с плавным блендингом между слоями для скрытия швов.
4. **Volumetric Fog (God Rays)**: В отдельном Compute Shader маршировать лучи от камеры до пикселя, проверяя затенение по CSM и аккумулируя свет через фазовую функцию Хеньи-Гринштейна (Henyey-Greenstein). Результат накладывается поверх HDR поверхностей.

---

## Этап 3: Advanced Screen-Space Effects
Для придания объема и фотореализма поверхностям.

**Реализация:**
1. **Z-Prepass**: Добавить предварительный проход рендера только глубины и нормалей (требуется для эффективных экранных эффектов и Forward+).
2. **HBAO+ (Horizon-Based Ambient Occlusion)**: Замена плоского Ambient. Ray-marching по depth-буферу в Compute Shader для расчета взаимного затенения микрорельефа.
3. **Hi-Z SSR (Screen-Space Reflections)**: 
   - Построить Hierarchical Z-Buffer (генерация mip-уровней для depth).
   - В Compute Shader выпускать лучи отражений, прыгая по mip-уровням для пропуска пустого пространства.
   - Fallback на Reflection Probes / Skybox, если луч уходит за экран.

---

## Этап 4: Global Illumination (The "Lumen-Lite" Approach)
В OpenGL 4.6 без аппаратного ускорения реализовать полный аналог Lumen невозможно, но мы можем создать гибридную систему.

**Реализация:**
1. **Light Probe Grid (Spherical Harmonics)**:
   - Раскидать трехмерную сетку проб по уровню.
   - Предрассчитать (запечь) или обновлять асинхронно в рантайме кубмапы для каждой пробы.
   - Свернуть освещение в сферические гармоники 2-го порядка (SH L2) и сложить в 3D текстуру.
   - Во время Forward-пасса интерполировать 8 ближайших проб для получения диффузного непрямого освещения.
2. **SSGI (Screen-Space Global Illumination)**:
   - Динамическое дополнение к пробам. Марширование лучей по полусфере нормали в экранном пространстве для переотражения цвета соседних пикселей.
   - Требует TAA (Temporal Anti-Aliasing) для временного накопления и подавления шума.

---

## Этап 5: Temporal Anti-Aliasing (TAA)
Текущий FXAA мылит картинку и не решает проблему субпиксельного алиасинга на тонких гранях.

**Реализация:**
1. Генерация матрицы проекции с субпиксельным джиттерингом (Halton sequence).
2. Рендер буфера векторов скорости (Velocity Buffer, RG16F).
3. В пост-процессе: репроекция предыдущего кадра по векторам скорости, Neighborhood Clamping (для предотвращения гостинга) и блендинг текущего и прошлого кадров.
4. TAA станет фундаментом для всех стохастических эффектов (SSGI, SSR, Volumetrics), позволяя рендерить их в пониженном разрешении с 1-2 семплами на пиксель.

---

## Дорожная карта интеграции в cjoka
1. Перевод движка на **Z-Prepass** и **Forward+ Clustering**. (Решает проблему света).
2. Интеграция **Cascaded Shadow Maps (CSM)**. (Решает проблему теней на открытых пространствах).
3. Добавление **Velocity Buffer** и реализация **TAA**. (Решает проблемы алиасинга и шума).
4. Навешивание **HBAO+** и **Hi-Z SSR**.
5. Эксперименты с **Probe Grid GI** или **SSGI**.
