# Lumen Global Illumination -- Technical Breakdown

## Architecture

Lumen -- гибридная система реального времени для глобального освещения (GI) и отражений
в Unreal Engine 5. Она не привязана к одному алгоритму, а масштабируется через иерархию
методов трассировки:

```
Screen-Space Tracing  -->  Software RT (SDF)  -->  Hardware RT (DXR/VK)
     (быстро)              (ядро Lumen)             (макс. качество)
```

Lumen разделяет интеграцию уравнения рендеринга на три кэша:

1. **Screen-Space Radiance Cache (SSRC)** -- финальный сбор освещения на экране
2. **World-Space Radiance Cache (WRC)** -- глобальное непрямое освещение
3. **Surface Cache (MeshCards)** -- хранение материалов и освещения на поверхностях

---

## 1. Surface Cache (MeshCards)

Ключевая оптимизация Lumen: вместо полного PBR-шейдинга в точке попадания луча,
используется заранее подготовленный кэш.

### Как это работает

1. На этапе загрузки для каждого статического меша генерируются **Mesh Cards** --
   6 осевых 2D-проекций, аппроксимирующих поверхность меша
2. Материальные свойства (Albedo, Normal, Roughness, Emissive) рендерятся
   на эти карты и упаковываются в **физический текстурный атлас**
3. В рантайме Lumen вычисляет освещение для текселей атласа
4. При попадании луча в объект -- простое семплирование атласа вместо полного
   шейдинга

```
Mesh Card Structure:
+--------+--------+
|  +X    |  -X    |   6 ортогональных проекций
+--------+--------+   для каждого меша
|  +Y    |  -Y    |
+--------+--------+   Хранят: Albedo, Normal,
|  +Z    |  -Z    |   Roughness, Emissive, Irradiance
+--------+--------+
```

### Многократные отскоки (Infinite Bounces)

Lumen достигает бесконечных отскоков через итеративную обратную связь:

- Кадр N: прямое освещение записывается в Surface Cache
- Кадр N+1: лучи из Surface Cache попадают в другие поверхности и семплируют
  их Surface Cache с кадра N
- Рекурсия через временную аккумуляцию -- свет отскакивает неограниченно

## 2. Software Ray Tracing через Signed Distance Fields

Ядро Lumen -- трассировка без аппаратного RT.

### Mesh Distance Fields (MDF)

Каждый статический меш имеет предвычисленное SDF (трехмерная текстура расстояний).

```
Sphere Tracing:
   p(0) ----d0----> p(1) ---d1---> p(2) -d2-> HIT
   
   p(i+1) = p(i) + d(i) * direction
   if d(i) < epsilon: HIT
```

**Ближняя геометрия (~2м)**: лучи маршируют по инстансным MDF для точного
контактного GI и самозатенения.

### Global Distance Field (GDF)

**Дальняя геометрия**: все MDF объединяются в низкоразрешенный GDF, организованный
как clipmap вокруг камеры.

```
GDF Clipmaps:
+-------------------+
|  128m (4 v/m)     |
|  +-------------+  |
|  |  64m (8v/m) |  |
|  | +---------+ |  |
|  | | 32m CAM | |  |
|  | +---------+ |  |
|  +-------------+  |
+-------------------+
```

При попадании луча координата точки пересечения проецируется на MeshCard,
и из Surface Cache берется исходящая радиация.

---

## 3. Screen-Space Radiance Cache (SSRC)

Финальный сбор GI -- не на каждый пиксель, а через пробы пониженного разрешения.

### Алгоритм

1. **Расстановка проб**: сетка 1/4 - 1/2 разрешения экрана с учетом
   разрывов глубины (edge-aware)
2. **Трассировка**: из каждой пробы выпускаются лучи (Fibonacci sphere)
   - Сначала Hi-Z марширование по depth-буферу
   - Затем Software RT через SDF
   - Или Hardware RT через BVH
3. **Хранение**: радиация в каждой пробе -- SH или октаэдральная карта
4. **Интерполяция**: билатеральный фильтр на полное разрешение
   (веса по глубине и нормали)

---

## 4. World-Space Radiance Cache (WRC)

Для дальних лучей Lumen использует иерархическую сетку проб в мировом пространстве.

- **Clipmap**: вложенные сетки, центрированные на камере
- **Пробы**: каждая проба трассирует лучи для сбора дальнего освещения
- **Fallback**: если короткий луч из SSRC не попал в ближнюю геометрию,
  он интерполирует направленную радиацию из WRC

Это радикально сокращает длину трассируемых лучей.

---

## 5. Lumen Reflections

Иерархия fallback'ов:

```
SSR (Hi-Z depth march)
  |-- hit: sample color buffer
  +-- miss: Software/Hardware RT
              |-- hit: sample Surface Cache
              +-- miss: sample sky / environment
```

- **Гладкие поверхности** (roughness < 0.3): точная трассировка луча
- **Грубые поверхности** (roughness > 0.3): Cone Tracing через Radiance Cache

---

## 6. Hardware Ray Tracing (HWRT)

Опциональный режим повышенного качества:

- Трассировка через BVH (TLAS/BLAS) вместо SDF
- Необходим для **динамической геометрии** (скелетные меши, персонажи)
- SDF плохо работает с тонкой геометрией (листва, решетки) -- HWRT решает это
- Даже с HWRT, шейдинг точки попадания идет через Surface Cache (не полный PBR)

---

## 7. Performance

### Ключевые оптимизации

| Техника | Назначение |
|---------|-----------|
| Temporal filtering | Трассировка распределяется по кадрам (checkerboard) |
| Spatial denoiser | Реконструкция сигнала из шумных трасс |
| Surface Cache amortization | Не все texeli обновляются каждый кадр |
| Screen-space probes | Финальный сбор на 1/4 разрешения |
| Clipmap GDF | Трассировка дальней геометрии за O(log N) |

### Типичные затраты (RTX 3070, 1080p)

- Lumen GI: ~4-6ms
- Lumen Reflections: ~2-3ms
- Surface Cache update: ~1-2ms (амортизировано)
- Total: ~8-12ms (из 16.6ms бюджета для 60 FPS)

---

## 8. Nanite + Lumen

Nanite создает микрополигональную геометрию, слишком плотную для BVH.

- Nanite генерирует **упрощенный fallback-меш** (proxy)
- Lumen работает с proxy для Surface Cache и HWRT BVH
- Высокоразрешенный depth-буфер Nanite дает точные screen-space трассы
- Proxy покрывает off-screen bounce lighting
- Расхождение маскируется фильтрацией SSRC

## 9. Что делает UE5 фотореалистичным помимо Lumen

### Virtual Shadow Maps (VSM)

Замена каскадных теней. Работает как виртуальная память:
- Сверхвысокое разрешение (16K x 16K), разбитое на страницы 128x128
- Обновляются только страницы с видимой геометрией или движением
- Пиксельно-точные тени с физически корректными полутенями

### Temporal Super Resolution (TSR)

Продвинутый временной апскейлер (аналог DLSS/FSR):
- Отслеживает субпиксельную историю
- Аккумулирует высокоразрешенное изображение из низкоразрешенного рендера
- Критичен, так как Lumen + Nanite слишком тяжелы для нативного 4K

### Volumetric Fog

- Воксельный объем тумана (Froxel Volume)
- Lumen инжектирует GI в объемный туман
- Непрямой свет естественно рассеивается в воздухе

### Subsurface Scattering

- Burley SSS модель для кожи, воска, листвы
- Интеграция с Lumen для непрямого подповерхностного рассеивания
